# 仕様書作成チェックリスト

## ユーザーストーリー 5W1H テンプレート

```md
## ユーザーストーリー: <機能名>

### Who（誰が）
- ユーザー種別:
- 権限レベル:
- 前提条件:

### What（何を）
- 実現したい機能:
- 対象データ:
- 操作範囲:

### When（いつ）
- 実行タイミング:
- 前提状況:
- 制約条件:

### Where（どこで）
- 実行環境:
- 画面・ページ:
- システム範囲:

### Why（なぜ）
- ビジネス価値:
- 解決する課題:
- 期待する結果:
```

## ストーリー品質チェック

- [ ] 5W1H の各軸が具体的に記述されているか
- [ ] 技術実装ではなくユーザー行動・価値に焦点が当たっているか
- [ ] 完了判定が明確（検証可能）か
- [ ] 他のストーリーに依存せず単独で理解できるか
- [ ] 曖昧表現（「早い」「使いやすい」）が数値化または除去されているか

## 機能要件 vs 非機能要件の分類

| 種別 | 内容例 | 出力先 |
|------|--------|--------|
| 機能要件 | UI動作・ビジネスルール・データ制約・エラー表示 | user-stories/, success-scenarios/, error-scenarios/ |
| 非機能要件 | 応答時間・同時接続数・可用性・セキュリティ方式 | requirements/ |

### 混在防止チェック

- [ ] ユーザーストーリーに性能・可用性が混入していないか
- [ ] 非機能要件に UI 動作・データ仕様が混入していないか
- [ ] 「何をするか」と「どのような品質で」が分離されているか

## 工程境界チェック（仕様整理フェーズで記載しないもの）

- エンドポイント URL パス
- JSON リクエスト / レスポンスの詳細構造
- データベーススキーマ
- 技術フレームワーク選定理由
- 実装パターン詳細

## 将来課題分離チェック

以下を含む内容は `future-work.md` に移動し現工程から除外する:

- [ ] 「将来的に」「次フェーズ」「後で検討」を含む機能
- [ ] MVP に含まれない拡張機能
- [ ] ユーザーが「先の話」と判断した要件

## 完了判定基準

- [ ] 全ファイルが命名規則に従って出力されているか
- [ ] ストーリーが 5W1H で記述されているか
- [ ] 成功/失敗シナリオに HTTP ステータスと UX 説明が両方あるか
- [ ] 機能要件と非機能要件が分離されているか
- [ ] API 詳細・技術実装詳細が含まれていないか
- [ ] 将来課題が future-work.md に分離されているか
