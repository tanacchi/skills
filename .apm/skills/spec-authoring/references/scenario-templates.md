# シナリオテンプレート

## 成功シナリオ

```md
## 成功パターン

### シナリオ: <シナリオ名>

**前提条件**:
- <システムやデータの初期状態>
- <ユーザーの認証・権限状態>

**実行手順**:
1. <具体的なアクション>
2. <具体的なアクション>

**期待結果**:
- **ユーザー体験**: <ユーザーが見る画面・メッセージ・次に取れる行動>
- **システム動作**: <ユーザーから見えるシステムの反応>
- **技術分類**: HTTP 200 OK / 201 Created / 204 No Content
```

## 失敗シナリオ

```md
## 失敗パターン

### エラーシナリオ: <エラー種別>

**発生条件**:
- <エラーが発生する具体的な状況>

**実行手順**:
1. <エラーを引き起こすアクション>
2. <システムの反応>

**期待結果**:
- **ユーザー体験**: <ユーザーが見るエラーメッセージ・利用継続可否・回復手段>
- **エラー対応**: <ユーザーが取れる次の行動・システムからの案内>
- **技術分類**: HTTP 400 / 401 / 403 / 404 / 409 / 422 / 500
```

## エラー種別分類

| 種別 | 説明 | 典型的な HTTP ステータス |
|------|------|------------------------|
| バリデーションエラー | 入力値の形式・範囲違反 | 400, 422 |
| 認証エラー | 未ログイン・セッション切れ | 401 |
| 認可エラー | 権限不足 | 403 |
| リソースエラー | データ不存在・重複 | 404, 409 |
| ビジネスルールエラー | 業務制約違反 | 400, 422 |
| システムエラー | サーバー障害・外部 API 障害 | 500, 503 |

## バリエーションパターンの観点

成功シナリオには以下のバリエーションも検討する:

- **境界値**: 最小値・最大値での動作
- **データパターン**: 異なるデータタイプでの正常動作
- **権限パターン**: 異なる権限レベルでの正常動作

## 後続工程への追跡性

| 仕様成果物 | 後続工程での用途 |
|-----------|----------------|
| ユーザーストーリー | DDD の集約・境界コンテキストの入力 |
| 成功/失敗シナリオ | BDD / API テスト / E2E の入力 |
| UI ストーリー | sitemap・flow・コンポーネント設計の入力 |
| 非機能要件 | アーキテクチャ / API / UI 設計制約の入力 |
